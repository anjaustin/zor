# TriX Execution Stack

**From Python shapes to GPU silicon at 19 billion ops/sec.**

## Overview

TriX shapes can execute on any substrate. The execution stack provides three tiers of performance:

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           EXECUTION STACK                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   ┌─────────────┐     ┌─────────────┐     ┌─────────────────────────────┐   │
│   │    HSOS     │     │   GILLIES   │     │      GILLIES Vulkan         │   │
│   │  (Python)   │ ──► │    (C)      │ ──► │        (GPU)                │   │
│   │             │     │             │     │                             │   │
│   │  3.2M ops/s │     │  900M ops/s │     │      19,000M ops/s          │   │
│   └─────────────┘     └─────────────┘     └─────────────────────────────┘   │
│                                                                              │
│        ×1                  ×280                    ×6,000                    │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

**The shape is substrate-independent.** The XOR polynomial `a + b - 2ab` computes identically whether interpreted by Python, compiled to C, or executed as a GPU shader.

## Layer 1: HSOS (Hollywood Squares Operating System)

**Module:** `trix.hsos`
**Performance:** ~3.2M ops/sec
**Use case:** Development, prototyping, debugging

HSOS is a distributed microkernel for addressable processor networks. No arrays, no batches—just processors and messages.

### Core Concepts

```python
from trix.hsos import Processor, Network, Message

# Create a network of processors
net = Network()
net.add(Processor(signature=0b1010, shape='xor'))
net.add(Processor(signature=0b0101, shape='and'))
net.add(Processor(signature=0b1100, shape='or'))

# Send a message - routes by Hamming distance
net.send(Message(target=0b1010, payload={'a': 1, 'b': 0}))

# Run until quiescent
net.run()
```

### Key Principles

1. **Deterministic message passing** - Messages route to processors by signature matching
2. **Bounded local semantics** - Each processor sees only its inputs
3. **Enforced observability** - Every message is logged
4. **Topology encodes algorithm** - Different wiring = different computation

### Frozen Shapes

HSOS provides 12 frozen shapes:

| Category | Shapes |
|----------|--------|
| **Primitives** | `xor`, `and`, `or`, `not`, `identity` |
| **Arithmetic** | `full_adder`, `half_adder` |
| **Stateful** | `accumulator`, `counter`, `latch` |
| **Routing** | `compare`, `mux`, `hamming` |

Each shape is a pure function: `(state, inputs) → (state, outputs)`

```python
from trix.hsos import get_shape

xor = get_shape('xor')
state, outputs = xor({}, {'a': 1, 'b': 0})
# outputs = {'result': 1}
```

## Layer 2: GILLIES (C)

**Module:** `trix.hsos.compile`
**Performance:** ~900M ops/sec
**Use case:** Production CPU deployment

GILLIES compiles HSOS networks to native C code. The compiler performs three passes:

1. **Analyze** - Enumerate processors, infer routing
2. **Allocate** - Assign port ranges to each processor
3. **Emit** - Generate C code

### Compilation

```python
from trix.hsos import Network, Processor
from trix.hsos.compile import compile_to_gillies

# Create network
net = Network()
for i in range(4):
    net.add(Processor(signature=i, shape='xor'))

# Compile to C
c_code = compile_to_gillies(net, "four_xor")
print(c_code)
```

### Generated Code

```c
/*
 * four_xor - Generated by HSOS → GILLIES Compiler
 *
 * Processors: 4
 * Ports used: 12
 */

#include "gillies.h"

int main() {
    gillies_context_t* ctx = gillies_create();

    // Invocations
    gillies_invoke(ctx, GILLIES_SHAPE_XOR, 0, 1, 2);
    gillies_invoke(ctx, GILLIES_SHAPE_XOR, 3, 4, 5);
    gillies_invoke(ctx, GILLIES_SHAPE_XOR, 6, 7, 8);
    gillies_invoke(ctx, GILLIES_SHAPE_XOR, 9, 10, 11);

    // Execute all shapes
    gillies_execute(ctx);

    gillies_destroy(ctx);
    return 0;
}
```

### Shape Implementation (C)

```c
static inline float gillies_xor(float a, float b) {
    return a + b - 2.0f * a * b;
}

static inline float gillies_and(float a, float b) {
    return a * b;
}

static inline float gillies_or(float a, float b) {
    return a + b - a * b;
}
```

## Layer 3: GILLIES Vulkan (GPU)

**Module:** `trix.native.vulkan`
**Performance:** ~19B ops/sec
**Use case:** Maximum throughput, hardware-agnostic GPU

GILLIES Vulkan executes shapes directly on GPU via Vulkan compute shaders. Works on all Vulkan-capable hardware:

| Vendor | Hardware |
|--------|----------|
| NVIDIA | GeForce, Quadro, Tegra |
| AMD | Radeon, RDNA, CDNA |
| Intel | Arc, Iris, UHD |
| Apple | M1/M2/M3 (via MoltenVK) |
| Qualcomm | Adreno (mobile) |
| ARM | Mali (mobile) |

### SPIR-V Shader

The XOR shape compiles to SPIR-V assembly:

```spirv
; XOR Compute Shader
; out[i] = a[i] + b[i] - 2.0 * a[i] * b[i]

OpCapability Shader
OpMemoryModel Logical GLSL450
OpEntryPoint GLCompute %main "main" %gl_GlobalInvocationID
OpExecutionMode %main LocalSize 256 1 1

%main = OpFunction %void None %funcType
%entry = OpLabel

  ; Load inputs
  %a = OpLoad %float %ptrA
  %b = OpLoad %float %ptrB

  ; Compute XOR: a + b - 2*a*b
  %sum    = OpFAdd %float %a %b
  %prod   = OpFMul %float %a %b
  %twice  = OpFMul %float %2.0 %prod
  %result = OpFSub %float %sum %twice

  ; Store result
  OpStore %ptrOut %result

OpReturn
OpFunctionEnd
```

## The Stack in Action

### Example: 8-bit Ripple Adder

**HSOS (Development)**
```python
from trix.hsos import Network, Processor

# Create 8 full-adder processors
net = Network()
for bit in range(8):
    proc = Processor(signature=bit, shape='full_adder')
    if bit > 0:
        proc.output_target = bit  # Chain carry
    net.add(proc)

# Test
net.set_inputs(0, {'a': 1, 'b': 1, 'c': 0})
net.run()
```

**GILLIES C (Production)**
```bash
# Compile network to C
python -c "
from trix.hsos import Network, Processor
from trix.hsos.compile import compile_to_gillies

net = Network()
for i in range(8):
    net.add(Processor(signature=i, shape='full_adder'))

print(compile_to_gillies(net, 'ripple8'))
" > ripple8.c

# Build and run
gcc -O3 ripple8.c gillies.c -o ripple8
./ripple8
```

**GILLIES Vulkan (GPU)**
```bash
# Run 16M additions on GPU
./gillies_vulkan_bench
# → 19.4 billion ops/sec
```

## Native Guardian Interface

The Guardian (training observer) is fully native - no PyTorch required:

```python
from trix.native import (
    NativeProgrammableTile,
    NativeProgrammableTileBank,
    NativeTrainingObserver,
    AdamOptimizer,
    mse_loss,
)

# Tiles are addressable, observable, modifiable
bank = NativeProgrammableTileBank(d_model=64, d_hidden=128, num_tiles=8)

# Read interface
sig = bank.tiles[0].read_signature()
up, down = bank.tiles[0].read_weights()

# Write interface (bounded modification)
bank.tiles[0].write_signature(new_sig, blend=0.1, reason='diversity_push')

# Control interface
bank.tiles[0].freeze()    # Lock modifications
bank.tiles[0].unfreeze()  # Allow modifications

# Observer monitors and intervenes
observer = NativeTrainingObserver(bank)
obs = observer.step(tile_idx)  # Returns metrics + applies interventions
```

### Observer Metrics

| Metric | Description |
|--------|-------------|
| `diversity` | How different tile signatures are (0-1) |
| `load_balance` | Std dev of tile usage |
| `num_unused` | Tiles receiving no traffic |

### Intervention Triggers

| Condition | Action |
|-----------|--------|
| `diversity < 0.3` | Push similar signatures apart |
| `load_max > 0.5` | Redistribute unused tiles |
| `num_unused > n/4` | Move unused toward popular |

## Binary Frozen Shapes

After training, shapes can be frozen to pure binary operations for maximum inference speed:

```c
// Polynomial (training)          Binary (inference)
shape_xor(a, b)  // a+b-2ab  →   shape_xor_binary(a, b)  // a ^ b
shape_and(a, b)  // ab       →   shape_and_binary(a, b)  // a & b
shape_or(a, b)   // a+b-ab   →   shape_or_binary(a, b)   // a | b
```

**On binary inputs {0, 1}, these are mathematically identical.**

### Performance

```
XOR on 1,000,000 elements:
  Polynomial: 0.009 ms (float32, 4 FLOPs/element)
  Binary:     0.003 ms (uint8, 0.125 ops/element)
  
  Speedup:    2.8x
  Memory:     32x smaller (1 bit vs 32 bits per element)
  Throughput: 117 GB/s
```

### Why So Fast?

| Metric | Polynomial | Binary | Ratio |
|--------|------------|--------|-------|
| Ops per element | 4 FLOPs | 0.125 XORs | 32x fewer |
| Bytes per element | 12 | 0.375 | 32x smaller |
| Cache fit (1M) | No (12 MB) | Yes (375 KB) | - |

Binary shapes process 8 elements per byte-level instruction. Data fits in L2 cache.

## Key Insight

> *"The shape doesn't care about the substrate."*

The XOR polynomial `a + b - 2ab` is a mathematical truth. It computes identically whether:

- **Interpreted** by Python (HSOS)
- **Compiled** to native code (GILLIES C)
- **Executed** as a GPU shader (GILLIES Vulkan)
- **Synthesized** to FPGA/ASIC (future)

This is substrate independence. The shape IS the computation.
