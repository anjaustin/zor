# ONNX to C Compiler

**Convert any ONNX model to a standalone native executable.**

*"ONNX is notation. Shapes are truth. C is execution."*

---

## Quick Start

```bash
# Convert ONNX to C
python tools/onnx2trix.py model.onnx model.c --emit-c

# Compile to native binary
gcc -O3 -DTRIXC_STANDALONE -I./include model.c -o model -lm

# Run
./model input.bin output.bin
```

That's it. Your neural network is now a native executable.

---

## What This Does

The `--emit-c` flag converts an ONNX model directly to C source code:

```
model.onnx                    model.c                      model
┌──────────────┐             ┌──────────────┐             ┌──────────────┐
│ ONNX Graph   │  ──────▶    │ C Source     │  ──────▶    │ Native       │
│ + Weights    │  onnx2trix  │ + Weights    │  gcc        │ Executable   │
│ (~1 MB)      │             │ (~3 KB)      │             │ (~70 KB)     │
└──────────────┘             └──────────────┘             └──────────────┘
```

**No PyTorch. No ONNX Runtime. No TensorFlow. Just a binary.**

## Command Line Options

```bash
python tools/onnx2trix.py [input.onnx] [output] [options]
```

| Option | Description |
|--------|-------------|
| `--emit-c` | Generate C code instead of Octave IR (JSON) |
| `--standalone` | Include `main()` for standalone binary (default: true) |
| `--no-standalone` | Omit `main()` for library mode |
| `--emit-header` | Also generate a `.h` header file |
| `--precision` | Weight precision: `fp16`, `fp32`, `fp64` (default: fp32) |
| `--no-weights` | Exclude weight data (shape info only) |
| `--verbose` | Print conversion details |

### Examples

```bash
# Basic: ONNX to standalone C
python tools/onnx2trix.py model.onnx model.c --emit-c

# Library mode (no main, for embedding)
python tools/onnx2trix.py model.onnx model.c --emit-c --no-standalone

# With header file
python tools/onnx2trix.py model.onnx model.c --emit-c --emit-header

# Half precision weights
python tools/onnx2trix.py model.onnx model.c --emit-c --precision fp16

# Just the Octave IR (JSON)
python tools/onnx2trix.py model.onnx model.trix
```

## Generated Code Structure

The generated C file has this structure:

```c
/* model.c - Generated by trixc */

#include <stdio.h>
#include <stdlib.h>
#include <math.h>
#include "trixc/onnx_shapes.h"

/* Configuration */
#define MODEL_INPUT_SIZE 768
#define MODEL_OUTPUT_SIZE 768

/* Weights (static const - goes in .rodata) */
static const float W_fc1_weight[768 * 3072] = { ... };
static const float W_fc1_bias[3072] = { ... };

/* Forward Pass */
void model_forward(const float* input, float* output) {
    float* t0 = alloca(3072 * sizeof(float));

    /* [0] MatMul */
    trix_onnx_matmul(input, W_fc1_weight, t0, 1, 3072, 768);

    /* [1] Add */
    trix_onnx_add(t0, W_fc1_bias, t0, 3072);

    /* [2] GELU */
    for (int i = 0; i < 3072; i++) t0[i] = trix_onnx_gelu(t0[i]);

    /* [3] MatMul */
    trix_onnx_matmul(t0, W_fc2_weight, output, 1, 768, 3072);
}

/* Standalone Main */
#ifdef TRIXC_STANDALONE
int main(int argc, char** argv) {
    float* input = malloc(MODEL_INPUT_SIZE * sizeof(float));
    float* output = malloc(MODEL_OUTPUT_SIZE * sizeof(float));

    // Read input, run model, write output
    ...
}
#endif
```

## Compilation

### Basic Compilation

```bash
gcc -O3 -DTRIXC_STANDALONE -I./include model.c -o model -lm
```

| Flag | Purpose |
|------|---------|
| `-O3` | Full optimization |
| `-DTRIXC_STANDALONE` | Enable the `main()` function |
| `-I./include` | Path to TRIXC headers |
| `-lm` | Link math library |

### Library Mode

```bash
# Compile as shared library
gcc -O3 -fPIC -shared -I./include model.c -o libmodel.so -lm

# Or static library
gcc -O3 -c -I./include model.c -o model.o
ar rcs libmodel.a model.o
```

### Cross-Compilation

```bash
# ARM (Raspberry Pi)
arm-linux-gnueabihf-gcc -O3 -DTRIXC_STANDALONE -I./include model.c -o model -lm

# RISC-V
riscv64-unknown-linux-gnu-gcc -O3 -DTRIXC_STANDALONE -I./include model.c -o model -lm

# WebAssembly
emcc -O3 -I./include model.c -o model.wasm
```

## Input/Output Format

The standalone binary reads and writes raw binary floats:

### Input File

```python
import numpy as np

# Create input
input_data = np.array([1.0, 2.0, 3.0, 4.0], dtype=np.float32)

# Save as binary
input_data.tofile('input.bin')
```

### Output File

```python
import numpy as np

# Read output
output_data = np.fromfile('output.bin', dtype=np.float32)
print(output_data)
```

### From stdin/stdout

```bash
# Pipe mode
cat input.bin | ./model > output.bin

# Or with files
./model input.bin output.bin
```

## Limitations (v1)

| Limitation | Workaround |
|------------|------------|
| Fixed dimensions only | Edit `#define`s and recompile |
| No broadcasting | Use explicit Expand ops in ONNX |
| Sequential graphs only | Flatten complex graphs |
| Weights embedded in C | Use `--no-weights` for external loading |
| Single-threaded | Add OpenMP pragmas manually |

## Troubleshooting

### "Unsupported op: X"

The operation isn't implemented yet. Options:
1. Simplify the ONNX model
2. Replace with supported ops
3. Implement the op in `onnx_shapes.h`

### "Dynamic dimension not supported"

TRIXC v1 requires fixed dimensions. Export your ONNX model with fixed shapes:

```python
torch.onnx.export(
    model,
    dummy_input,
    "model.onnx",
    input_names=['input'],
    output_names=['output'],
    dynamic_axes=None  # Fixed shapes
)
```

### Compilation Errors

Make sure the include path is correct:
```bash
gcc -I/path/to/trixc/include ...
```

### Wrong Output Values

1. Check input format (must be raw float32 binary)
2. Verify input size matches model expectation
3. Compare with ONNX Runtime output

## How It Works

1. **Parse ONNX**: Extract graph, weights, and shapes
2. **Build Tensor Map**: Map ONNX names to C identifiers
3. **Infer Shapes**: Calculate intermediate buffer sizes
4. **Emit Weights**: Convert to `static const float[]`
5. **Emit Forward**: Chain shape calls in topological order
6. **Emit Main**: Add I/O handling for standalone mode

The generated code calls frozen shapes from `onnx_shapes.h`. These shapes are mathematical facts, not learned approximations:

```c
// These are exact on their domains
float y = trix_onnx_gelu(x);      // x * sigmoid(1.702x)
float y = trix_onnx_sigmoid(x);   // 1 / (1 + exp(-x))
trix_onnx_matmul(A, B, C, M, N, K);  // Standard matrix multiply
```
