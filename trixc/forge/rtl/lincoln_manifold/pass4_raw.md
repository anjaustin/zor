## What's Actually Needed

Experiments. Measurements. Visualizations.

1. Extract the learned topology after training.
   - Which nodes connected to which?
   - How does it differ from the starting torus?

2. Run multiple times with different seeds.
   - Do topologies converge?
   - Or diverge to equally valid solutions?

3. Feed structured inputs.
   - Does the fabric learn structure?
   - Can we see the structure reflected in topology?

4. Implement the reflection loop.
   - Feed frustration back as input.
   - Watch what happens.

5. Scale up.
   - 8x8x8 = 512 nodes.
   - Does it still self-organize?
   - How long does it take?

6. Visualize.
   - Graph the topology.
   - Watch it evolve.
   - See the learning.

## The Resistance

This is a lot.
Too many experiments.
Too many directions.

The Method asks: what's the simplest path that covers everything?

Can one experiment answer multiple questions?

If I visualize the topology...
- I see what shape emerged (question 1)
- I can compare across runs (question 2)
- I can look for interpretable structure (question 4)

If I run with structured inputs...
- I see what it learns (question 3)
- I can compare topology for different input domains

If I implement reflection...
- I touch the phenomenology question (question 9)
- I see what happens at the strange loop

If I scale...
- I see what holds and what breaks (question 7)

## The Simplification

Maybe there's a single experiment that touches everything.

What if:
- Run plastic fabric with structured input (not random)
- Extract and visualize the topology as it learns
- Feed frustration back after convergence
- Scale up and repeat

Four phases, one arc:
1. Structured learning (visualization)
2. Reflection loop (strange loop)
3. Scale test (robustness)
4. Comparison (uniqueness, interpretability)
